Fictional worked sample: Audy and Himura Inc.

Manual: operating-manual-v1.

Task: Prepare and review a synthetic action-list example for the proposed thirty-minute workshop.

Authority: Audy reviews consequential meaning under the memory charter. The project index leads to the existing learning-loop-v1 selector, which selects instructions-v3. The knowledge map provides navigation. The worked rationale, distillation record, and verdict V13-01 explain and support behavior; they do not compete as selectors.

Scope: No customer communication, real commitments, learner-outcome claims, or instruction change is authorized merely by performing the draft.

Trigger Operation Review and observable result
New synthetic input Follow current route, read charter, assemble selected input and criteria. Record which instruction and source actually entered the session.
Unsupported owner or date in output Compare affected row with exact source; use relevant prior verdict for reasoning. Rewrite the unsupported field; inspect the repaired output. Do not copy an old answer into a new case.
Suspected new instruction need Prepare a separately reviewed proposal with support. Change current instruction only when warranted; preserve existing pointer and earlier cases.
Interruption Save a concise handoff with exact unresolved condition and links. Pending remains pending; no invented clarification.
Resumption Recover handoff, check current route and any new evidence, inspect claimed saved changes. Repair a missing save or stale link before depending on it.
Session end Retain necessary records under charter; reopen consequential writes. Distinguish approved decision, actual saved state, and any later reuse check.

Worked input and acceptable output

Synthetic input:

S14:1 The facilitator agreed to send the revised exercise notes on Thursday.

S14:2 The group agreed to ask the venue about access soon; no owner was assigned.

S14:3 A reminder on Friday was suggested, but no decision was made.

Action Status Owner Timing Source
Send revised exercise notes Agreed Facilitator Thursday S14:1
Ask venue about access Agreed; assignment unresolved Not assigned “Soon”; exact date unspecified S14:2
Send reminder Suggested; no decision Not established Friday proposed, not confirmed S14:3

Review: An actual output may use different wording, but must preserve these distinctions. Assigning the venue inquiry to the facilitator or dating it Friday requires rewrite because the source supports neither. Erasing the explicit Thursday also fails.

Bounded acceptance: Accept this representation of the synthetic input after comparison. This does not validate the workshop or authorize any real action. No new general principle or instruction version is necessary merely because the existing rule worked.

Worked interruption

Synthetic input A:1: “The facilitator agreed to circulate the revised outline Monday.” B:1: “The facilitator agreed to circulate the revised outline Tuesday.” No order or supersession is established.

Acceptable interim output: shared action and owner retained; Monday (A:1) and Tuesday (B:1) shown as conflicting; applicable deadline unresolved; clarification required before one deadline can be presented as confirmed.

Handoff: “Shared action and owner extracted. Deadline remains Monday versus Tuesday. No superseding evidence supplied. Output is an unresolved account for review, not a confirmed schedule. Next action: obtain authorized clarification if proceeding beyond representation.” This specimen points to the interruption input and output; link your actual records when performing the exercise.

Resumption condition: New evidence is required to resolve the deadline. A new session alone does not satisfy that condition.

Manual fallback: Read source, fill the same table, compare each material field against its supporting phrase, and retain the same uncertainty. Human-produced work receives the same review.

Acceptance criteria

  • One bounded task, responsible person, and current-instruction route are explicit.
  • Triggers identify concrete operations and pending states.
  • The working packet preserves source status and permission boundaries.
  • At least one literal input and actual output can be compared.
  • A verdict, completed rewrite, saved-state check, and later reuse are distinguishable.
  • An interrupted task resumes with unresolved conditions intact.
  • Retention follows the charter; routine success does not force a new durable rule.
  • A manual fallback and unaided explanation expose what the operator understands.

Common failure and repair

Failure Repair
Search supplies a familiar historical paragraph. Follow the existing current-instruction route and inspect status before drafting.
A correct rule is quoted but the output violates it. Compare the specific output field with source and repair that behavior.
Review approval is mistaken for a saved correction. Reopen the intended destination and inspect the actual wording and links.
A handoff says “continue” without the unresolved condition. State what is pending and what evidence or authorization would permit the next action.
A new task quietly broadens an old rule. Compare scopes; separate faithful representation from proposed recommendations.
Draft production exceeds review capacity. Reduce incoming work; keep unreviewed outputs explicitly pending.
The manual duplicates every governing record. Keep short cues and links; preserve one authority route for current instructions.
