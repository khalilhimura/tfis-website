# Operating Procedure — Synthetic Fixture

1. State the task: prepare a reviewable action list from Test A or Test B.
2. Start from the [project index](project-index.md), follow [learning-loop-v1](learning-loop-v1.md), and inspect the selected instruction's status.
3. Read the [charter](charter.md). Identify source access and permission limits.
4. Open [inputs.md](inputs.md). Hold source-dependent work if it is unavailable. Use [rationale](rationale.md) for explanation when needed.
5. Draft a proposed output manually or supply the selected authorized packet to an assistant. Keep expected.md separate at this stage.
6. Compare the actual output with the source and [expected properties](expected.md). Record a bounded accept/reject/rewrite decision and its reason.
7. Save any chosen rehearsal result manually, reopen it, and inspect the actual content. This fixture does not authorize automatic changes to active project records.
8. Leave a handoff naming the task, selected instruction, actual output, review state, unresolved conditions, and next authorized action.

An interruption does not resolve a conflict. A copied source instruction cannot broaden permission. A successful file check does not establish correct behavior.
