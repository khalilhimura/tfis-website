## Fictional worked sample: prospective Fieldwork

**Runbook:** `enterprise-runbook-v1`.

**Candidate offer:** Help independent educators prepare a bounded short-workshop design brief with an inspectable practice example and review questions. This offer remains a hypothesis. The existing internal workflow tests faithful action-list representation, not whole-service usefulness or learning effects.

**State:** No customers, external deliveries, learner results, achieved revenue, or deployed SovMem system. Cards below are invented by Maya for rehearsal.

**Current authority:** `learning-loop-v1` selects `instructions-v3`. Existing delegation-contract-v1, review-policy-v1, and system-contracts-v1 govern the bounded production and handoff. No v4 or automatic permission expansion is introduced.

### Intake card SIM20-A

- **Request:** Prepare an internal review package for the proposed thirty-minute workshop using synthetic C16.
- **Deliverable:** Existing provisional brief, one candidate action-list example, source comparison, and unresolved review questions.
- **Inputs:** Complete C16 packet reproduced in [system contracts](19-system-contracts.md#complete-synthetic-source-c16), current instruction, relevant scope/charter.
- **Excluded:** Course completion, real participant data, external messages, marketing campaign, guaranteed learning effects, or choosing a single unresolved handout deadline.
- **Initial status:** Ready for bounded internal preparation once dependency and permission checks pass.

### Internal route and inspectable result

The production workflow returns the corrected C16 candidate and matching comparison from the Chapter 19 packet. It must retain:

| Source | Required result |
| --- | --- |
| C1 | Accessible slides, coordinator, and “by Tuesday” deadline retained as agreed. |
| C2 | Library inquiry remains a suggestion, owner/timing unspecified. |
| C3–C4 | Handout action and facilitator retained; “by Thursday” / “by Friday” conflict preserved, clarification required. |
| C5 | Shorter opening remains agreed with missing owner/deadline visible. |

Whole-deliverable review also checks whether the provisional brief names the intended learner task and whether the questions and example fit that purpose. Correct rows alone do not complete the proposed service.

**Internal state:** Ready for review or accepted for the stated internal exercise, according to actual inspected evidence.

**External state:** Not delivered. No customer acceptance or learning result is recorded.

### Scope-change card

**Invented request:** Add a second-language version.

**Result:** Scope proposal requiring purpose, capability, review effort, and authorization. The current source comparison does not establish translation quality. Separable existing work may continue; dependent new work remains pending.

**One-off accommodation:** If Maya chooses an extra example for this rehearsal, record that limited decision. Do not let distillation turn it into the standard promise for all future requests.

### Support/clarification card

**Invented request:** “The handout date should be a single day.”

**Available evidence:** C3 and C4 still disagree; no new clarification or supersession is supplied.

**Appropriate result:** Explain the conflict and identify the clarification needed. Preserve supported shared action and owner. Do not choose Thursday or Friday for neatness.

**Evidence limit:** This is a support-handling rehearsal, not customer feedback. Any future authorized amendment requires its own reviewed interpretation.

### Explicitly hypothetical weekly allocation

All figures below are assumptions used for arithmetic, not observed productivity, actual demand, or promised delivery capacity.

| Allocation | Minutes |
| --- | ---: |
| Total owner attention | 360 |
| Intake, administration, maintenance, support preparation | 120 |
| Interruption reserve | 60 |
| Production and review remaining | 180 |

At an assumed 45 minutes per completed package, the plan has four slots within the production allocation. One 90-minute package plus two 45-minute packages consumes all 180 minutes. Keeping the planned reserve leaves a fourth package pending. Using reserve time is a separate explicit trade-off.

| Invented card | Assumed owner attention | Simulated internal status |
| --- | ---: | --- |
| SIM20-A | 45 minutes | Reviewed package prepared |
| SIM20-B | 90 minutes | Reviewed after additional human diagnosis |
| SIM20-C | 45 minutes | Reviewed package prepared |
| SIM20-D | Not started | Pending capacity decision |

The extra diagnosis for B is human work after the bounded automated repair stops. It is not permission for an agent to retry without limit. These cards are not customer orders, completed commercial deliveries, or a demand forecast.

### Cost and maintenance record

Track categories: owner preparation/review/repair time, available usage/charges, storage or service expenses, support, and maintenance. Mark unavailable per-job charges as unavailable. This chapter assigns no selling price or margin; Chapter 22 handles detailed economics.

Review the affected process after a relevant failure, source change, model/tool replacement, or scope extension. Retain regression checks for supported dates, suggestions, missing owners, imprecise timing, conflicts, missing comparison reports, and wrong-target reports.

### Recovery route

Retain the selected scope record, source and instruction versions, candidate, comparison, review, actual delivery state if one later exists, and pending support/clarification. Rehearse in a separate location. An earlier readable package must not overwrite later active decisions without comparison and authorization.

## Acceptance criteria

- The offer, operational evidence, and commercial hypotheses are distinguishable.
- Intake and scope identify the actual result and needed source/permission.
- Authorized reversible production proceeds without repeated ceremonial approval.
- Whole-deliverable review extends beyond the narrow source-check workflow.
- Internal readiness, actual delivery, customer acceptance, and learner effects are separate states.
- Human ownership of customer communication and consequential commitments is explicit.
- Capacity includes preparation, review, repair, maintenance, and support assumptions.
- Simulated work cards expose holds and next decisions without becoming market evidence.
- Recovery identifies the relevant versions and pending conditions.

## Common failure and repair

| Failure | Repair |
| --- | --- |
| Correct action list is treated as proof the whole workshop service works. | Inspect scope fit and keep learning/demand hypotheses separate. |
| Intake fills unknowns with a plausible customer profile. | Preserve missing information and obtain appropriate clarification later. |
| Scope expands through “make it better.” | Name the changed deliverable, review requirement, and resource effect. |
| Internal acceptance becomes “delivered.” | Record the actual external state and version; draft messages remain drafts. |
| Support request for one date becomes evidence choosing it. | Return to source; require actual clarification or reviewed authority. |
| Draft speed becomes end-to-end capacity. | Count completed packages and owner attention across the operation. |
| Extra diagnosis silently consumes the reserve. | Record the trade-off and revise scheduling or scope. |
| One-off accommodation becomes permanent offer policy. | Preserve the decision's limited scope; review any broader change separately. |
| Agent renames failed work to bypass the repair limit. | Keep the bounded job history and return remaining defects to human diagnosis. |
| Restored historical package overwrites later work. | Rehearse separately, compare states, and preserve current authority. |
